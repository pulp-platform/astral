# OBPMark benchmarks on the Astral PULP integer cluster

This directory contains the source of the OBPMark #1.1 (Image Calibration and
Correction) benchmark ported to the Astral heterogeneous SoC. The benchmark is
offloaded from the Cheshire host (CVA6, RV64) to the PULP integer cluster
(8x RV32IMC cores with the XpulpV2/xgap9 SIMD extension) and run in RTL
simulation with QuestaSim.

## What lives here

Each subdirectory is one benchmark variant and contains a cluster-side source
file (`.c`) and its `Makefile`. These are the **only** files that must be
version-controlled; everything downstream (`build/`, `.h`, `payload.h`, ELFs)
is generated by the flow described below and must NOT be committed.

| Directory                          | Variant                                                        |
|------------------------------------|----------------------------------------------------------------|
| `obpmark_1_1`                      | Reference cluster port (single core)                           |
| `obpmark_1_1_seq`                  | Sequential cluster (1 core, baseline)                          |
| `obpmark_1_1_par`                  | Parallel cluster (8 cores, SPMD)                               |
| `obpmark_1_1_par_simd`            | Parallel + 16-bit SIMD on f_offset and f_2x2_bin               |
| `obpmark_1_1_par_simd_v2_prof`    | As above + partial SIMD f_scrub + per-kernel cycle profiling   |
| `obpmark_1_1_par_simd_v3_prof`    | As v2 but f_scrub mean via add2div2 (fully SIMD) + profiling   |

The host-side counterparts (sequential CVA6 and SMP CVA6 reference
implementations) and the offload driver live under
`sw/tests/bare-metal/hostd/` in the main repository, not here.

## Where the build actually happens

IMPORTANT: the build system compiles the cluster tests from inside the
bender checkout, NOT from this directory:

```
.bender/git/checkouts/pulp_cluster-<hash>/regression_tests/astral/<test>/
```

That checkout is a local copy of the `pulp_cluster` dependency, recreated by
`bender update` and excluded from version control. The sources kept here are
the authoritative copies. To build a benchmark, copy its directory
(source + Makefile) into the bender checkout's `regression_tests/astral/`
folder, then run the flow below. Keeping the copies here means the work is not
lost when bender refreshes the checkout.

A test directory needs exactly two files:

- `<name>.c`    the cluster source
- `Makefile`    with `PULP_APP_SRCS` pointing at that exact `.c` filename:

```make
PULP_APP = test
PULP_APP_SRCS = <name>.c
PULP_CFLAGS = -O3 -I$(PULPRT_HOME)/drivers/include
include $(PULP_SDK_HOME)/install/rules/pulp.mk
```

The `-I$(PULPRT_HOME)/drivers/include` is required so the runtime's UART
driver header is found; without it the build still links but emits
implicit-declaration warnings for `uart_write`.

## Build and run flow

The pipeline turns a cluster `.c` into a host binary that QuestaSim executes:

```
<name>.c
   | pulp-runtime build (RV32 gcc)
   v
build/test/test            (cluster ELF)
   | elf2header.py
   v
<name>.h                   (C array with the cluster binary + load vectors)
   | copied to payload.h, compiled into the offloader
   v
pulpd_offloader_blocking.<name>.car.dram.elf   (host CVA6 ELF)
   | QuestaSim
   v
simulation (UART prints results)
```

### 0. Environment (once per shell, ORDER MATTERS)

```bash
cd <repo-root>
source env/env-iis.sh                                   # IIS toolchain + bender in PATH
source .bender/git/checkouts/pulp_cluster-<hash>/pulp-runtime/configs/astral-cluster.sh
```

`env-iis.sh` must come first: it puts the RISC-V toolchain and `bender` on the
PATH. `PULPD_ROOT` in the makefiles is computed by `bender path pulp_cluster`,
so if bender is missing the whole test list is empty and every target fails
with "No rule to make target". `astral-cluster.sh` then exports
`CONFIG_NO_FC=1` (selects the correct crt0 variant for the FC-less Astral
cluster) and `PULPRT_TARGET=astral-cluster`. Verify with:

```bash
echo "CONFIG_NO_FC=$CONFIG_NO_FC  PULPRT_HOME=$PULPRT_HOME"
```

### 1. Build the cluster binary

```bash
TEST=obpmark_1_1_par_simd_v2_prof
CHK=.bender/git/checkouts/pulp_cluster-<hash>/regression_tests/astral
make -B CONFIG_IO_UART=2 $CHK/$TEST/build
```

- `CONFIG_IO_UART=2` MUST be passed on the command line (not as an env var):
  the runtime's `configs/default.mk` sets it to 0 with a plain `=`, which would
  override an env value. Value 2 routes cluster `printf` through the host UART
  driver (`uart_write` + flush, with LSR check) so output is captured by the
  testbench. With the default 0, prints are written to a device the testbench
  does not capture and nothing appears.
- `-B` forces a rebuild ignoring timestamps; needed when only flags or env
  changed, since make tracks files, not variables.

The build copies the ELF to `sw/tests/bare-metal/pulpd/$TEST.elf`.

### 2. Generate the header

```bash
make $(pwd)/sw/tests/bare-metal/pulpd/$TEST.h
```

The header rule target is an ABSOLUTE path, so it must be invoked with an
absolute path (`$(pwd)/...`). Calling it with a relative path gives
"No rule to make target". (Fallback: run the script directly with
`./.venv/bin/python scripts/elf2header.py --binary <build>/test/test
--vectors sw/tests/bare-metal/pulpd/$TEST.h`.)

### 3. Build the offloader

```bash
rm -f sw/tests/bare-metal/hostd/pulpd_offloader_blocking.$TEST.car.dram.elf
make car-pulpd-sw-offload-tests
```

This template copies each `<test>.h` to `payload.h`, compiles the offloader,
and removes `payload.h`  once per available header. It fails only if some
header is missing, so make sure step 2 ran for the test you want.

### 4. Simulate

```bash
make car-vsim-sim-run \
  CHS_BINARY=./sw/tests/bare-metal/hostd/pulpd_offloader_blocking.$TEST.car.dram.elf \
  DEBUG=1
```

The UART log ends with the benchmark report: elapsed cycles, throughput,
`Output[0][0]` (reference value 125700), and  for the `_prof` variants  the
per-kernel cycle breakdown.

## Data buffers must be in TCDM

Static data buffers used by the cluster must be placed in the `.heapsram`
section (macro `HEAPSRAM` in the sources), which the linker maps to L1/TCDM.
Otherwise they end up in the ELF payload, `_start` shifts above the expected
boot address, and the cluster fails to boot. `malloc` is not available in this
runtime.

## Notes on the SIMD variants

The 16-bit SIMD vectorization uses the `v2u`/`v2s` vector types (two 16-bit
lanes in a 32-bit word) with native `+`/`-` operators, which the compiler maps
to `pv.add.h`/`pv.sub.h`. Verify vectorization on the ELF with:

```bash
riscv32-unknown-elf-objdump -d sw/tests/bare-metal/pulpd/$TEST.elf | grep 'pv\.'
```

- `f_offset` and `f_2x2_bin` vectorize cleanly (data contiguous, no overflow /
  a single 32-bit reduction at the end).
- `f_scrub` sums four temporal frames; the sum exceeds 16 bits, so v2 keeps
  only the loads in SIMD, while v3 computes the 4-frame mean entirely in SIMD
  via chained `add2div2` (`pv.add.h.div2`). The chained halvings truncate, so
  v3's output must be checked against the reference value.
